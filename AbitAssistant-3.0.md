### 🏗 Загальна структура (Monorepo)
Проєкт переходить від моноліту на Python до модульної архітектури на Go. Використовуємо стандарт **Standard Go Project Layout** для максимальної чистоти та масштабованості.

* **`cmd/` — Точки входу:**
    * `cmd/bot/main.go` — лише запуск Telegram-бота.
    * `cmd/desktop/main.go` — запуск Wails-додатка.
    * `cmd/server/main.go` — запуск сервера для сайту
* **`pkg/` — Публічне "Ядро" (Core):**
    * `pkg/parser/` — універсальний парсер (vstup.osvita.ua, abit-poisk).
    * `pkg/abit/` — структури даних (Student, NMT, ВНЗ) та логіка розрахунку балів.
    * `pkg/calculator/` — алгоритм "The Technique" для оцінки реальних шансів.
    * `pkg/visualizer/` — інтерфейс для візуалізації графіків.
    * `pkg/.../` — всі інші корисні інтерфейси
* **`internal/` — Приватна реалізація:**
    * `internal/bot/` — хендлери, меню та логіка діалогів Telegram.
    * `internal/desktop/` — Go-бекенд для Wails.
    * `internal/server/` — Логіка для сервера.
    * `internal/visualizer/` — "важкий" модуль для генерації графіків (Matplotlib-style).
    * `internal/.../` — всі інші логіки.
* **`wails-frontend/`** — інтерфейс десктоп-версії на **Svelte + TypeScript**.
* **`server-frontend/`** — інтерфейс сайт-версії на **Svelte + TypeScript**.

### 🛠 Фішки збірки (Release alias)
Для створення мінімального статичного бінарника використовуємо:
`CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o abitassistant ./cmd/bot`

* **`CGO_ENABLED=0`**: повна незалежність від системних бібліотек (ідеально для `scratch`).
* **`-ldflags="-s -w"`**: видаляє дебаг-інфо, зменшуючи вагу файлу на ~30%.
* **`scratch`**: порожній Docker-образ вагою 0 байт, де лежить тільки твій бінарник.

1.  **Модульність:** Можна підключити `pkg/parser` до будь-якого іншого проєкту через `go get`.

3.  **Швидкість:** Парсинг на горутинах буде в рази швидшим за асинхронність Python.
